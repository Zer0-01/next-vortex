# Fresh Next.js Stack Design

## Objective

Replace the current application with a completely blank, current Next.js starter while preserving the repository's `.git` directory and history. No existing pages, components, styles, public assets, or application configuration will carry into the replacement.

## Technology Baseline

- Use npm, matching the repository's existing package-manager convention.
- Require Node.js 20.9 or newer; the current environment is Node.js 22.13.1 with npm 10.9.2.
- Resolve the current releases at execution time through `create-next-app@latest`, `shadcn@latest`, and `motion@latest`, then record the resolved versions in `package-lock.json`.
- Use TypeScript, ESLint, the App Router, a `src/` directory, Turbopack, and the `@/*` import alias.
- Use Tailwind CSS through the configuration generated by current Create Next App and supported by the current shadcn/ui CLI.

## Rebuild Strategy

Create and validate the replacement application in a temporary staging directory first. After the scaffold succeeds, remove every item from the repository root except `.git`, move the staged application into the repository root, and initialize shadcn/ui there. This minimizes the interval during which the working tree has no usable project and keeps Git metadata out of all deletion targets.

The setup sequence follows the official tools independently:

1. Scaffold the application with `create-next-app@latest` and explicit non-interactive options for npm, TypeScript, ESLint, Tailwind CSS, App Router, `src/`, and the `@/*` alias.
2. Initialize shadcn/ui with `shadcn@latest init`, using its current defaults and generated `components.json`/CSS integration. No shadcn components are added because the requested result is a blank foundation.
3. Install `motion@latest`. Motion will be available from `motion/react`; the starter page will not add decorative animation merely to demonstrate the dependency.

Official references:

- Next.js installation: <https://nextjs.org/docs/app/getting-started/installation>
- Tailwind CSS with Next.js: <https://tailwindcss.com/docs/installation/framework-guides/nextjs>
- shadcn/ui installation: <https://ui.shadcn.com/docs/installation>
- Motion for React installation: <https://motion.dev/docs/react-installation>

## Resulting Project

The repository will contain the standard minimal Next.js application and tool configuration generated by the current official CLIs. The home route will be reduced to neutral starter content if the generated template includes promotional content. There will be no migrated business UI, routes, images, or custom components.

Expected root-level artifacts include `package.json`, `package-lock.json`, Next.js and TypeScript configuration, ESLint configuration, PostCSS configuration, `components.json`, `public/`, and `src/app/`. Generated framework metadata and dependencies such as `.next/` and `node_modules/` remain ignored.

## Failure Handling

- Do not delete the existing working tree until the temporary Next.js scaffold completes successfully.
- Stop if the installed Node.js version does not meet Next.js requirements.
- If any official CLI or package installation fails, retain the successfully staged or replaced files for diagnosis and report the failing command; do not conceal the failure with hand-written substitute configuration.
- Never remove or modify `.git` as part of cleanup.

## Verification

The rebuild is complete only when all of the following pass from the repository root:

1. `npm run lint`
2. `npm run build`
3. `npm ls next react react-dom tailwindcss @tailwindcss/postcss motion`
4. `npx shadcn@latest info` (or the current documented non-mutating project-info equivalent if the command has changed)
5. Git status confirms the intended full-tree replacement while `.git` history remains accessible.

No browser-level feature tests are required because this scope creates only a blank framework foundation with no application behavior.
